# learning-php

Учебный проект: изучение PHP и качества кода. Код унаследован от курса по Docker и по ходу уроков переписывается.

Приложение считает посещения страницы и пишет их в PostgreSQL.

## Стек

nginx → PHP-FPM 8.5 → PostgreSQL 18. Описан в `compose.yaml`.

## Запуск

```bash
cp .env.example .env
docker compose up -d --build
docker compose exec php composer install
```

Сайт: `http://localhost:8081`, база наружу на порту 5433.

Порты разведены с проектом `learning-docker` — оба стека могут работать одновременно.

## Песочница

Файл `sandbox.php` в корне — черновик для примеров из уроков:

```bash
docker compose exec php php sandbox.php
```

## Структура

| Путь | Что |
|---|---|
| `public/` | точки входа, видны браузеру |
| `src/` | классы, пространство имён `App\` |
| `sandbox.php` | черновик, запускается вручную |
| `docker/` | Dockerfile и конфиги nginx и PHP |

## Классы

| Класс | Назначение |
|---|---|
| `App\Visit` | один визит: идентификатор и время, неизменяемый |
| `App\VisitRepository` | работа с таблицей `visits` |
| `App\Database` | подключение к PostgreSQL |
| `App\Greeter` | заглушка из учебного задания |

## Программа

1. ООП — классы, инкапсуляция, наследование и композиция, интерфейсы, исключения
2. PSR и PHP-FIG
3. Composer и автозагрузка PSR-4
4. Качество кода, нейминг, PSR-12
5. MVC
6. Laravel или Symfony

## Что предстоит исправить

Известные недостатки — они же материал уроков:

- таблица `visits` создаётся из кода при заходе на страницу, должна создаваться миграцией
- `Database::connect()` — статический метод, зависимость невозможно подменить
- вся логика страницы свалена в `public/db.php`
- в `public/` лежат тестовые скрипты `info.php` и `db.php`
- `src/Greeter.php` — класс без состояния, по сути функция в обёртке
